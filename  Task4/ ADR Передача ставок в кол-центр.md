# Передача ставок в кол-центр

**Название задачи:**

Передача актуальных ставок по депозитам в кол-центр и партнёрский кол-центр

### **Автор:**

Команда цифровой трансформации

### **Дата:**

27 марта 2025

### **Функциональные требования**


| **№** | **Действующие лица или системы** | **Use Case**                                        | **Описание**                                                                                                                                                             |
| :----: | :-------------------------------------------------------- | :-------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
|   1   | Менеджер кол-центра                      | Просмотр актуальных ставок  | Менеджер видит актуальные ставки в своей системе для консультации клиентов                                      |
|   2   | Система кол-центра                        | Получение ставок                     | Получает ставки от микросервиса депозитов через REST API                                                                               |
|   3   | Партнёрский кол-центр                  | Получение файла со ставками | Получает экспортированный файл со ставками от банка в согласованном формате                                    |
|   4   | Микросервис депозитов                 | Формирование файла ставок    | Экспортирует файл ставок по расписанию и сохраняет его во внутреннем репозитории для партнёров |
|   5   | Администратор                                | Загружает файл партнёру        | Отправляет файл партнёру вручную или по email, т.к. нет автоматической интеграции                                 |

### **Нефункциональные требования**


| **№** | **Требование**                                                                                                                                 |
| :----: | :------------------------------------------------------------------------------------------------------------------------------------------------------- |
|   1   | Передача ставок в кол-центр должна происходить по API                                                          |
|   2   | Обновление ставок должно быть регулярным (например, 1 раз в день)                                    |
|   3   | Для партнёрского кол-центра возможен только формат файлов (CSV, XLSX)                                  |
|   4   | Доступ к API ставок только внутри периметра банка                                                                 |
|   5   | Файл должен формироваться в безопасном месте и контролироваться вручную                   |
|   6   | Использование существующих технологий — MS SQL или Oracle для хранения, .NET для API                |
|   7   | Возможность расширения на другие каналы в будущем (например, мобильное приложение) |

### **Решение**

#### Диаграмма контекста (C4):

* **Микросервис депозитов** выступает центральной точкой данных о ставках
* **Система кол-центра** делает REST API-запросы к микросервису, чтобы получить актуальные ставки в режиме онлайн
* **Микросервис депозитов** ежедневно формирует файл ставок (CSV/XLSX)
* **Администратор** банка передаёт этот файл партнёрскому кол-центру вручную (по email или внутреннему каналу)

#### Диаграмма компонентов (C4): RoadMap_bank_Standart.drawio

**Микросервис депозитов**:

* API ставок (GET /rates) — доступен только внутри сети банка
* Экспортёр ставок — формирует файл из БД по расписанию (CRON/Windows Task Scheduler)
* Сервис хранения файлов — безопасный внутренний shared-диск или облачный бакет (внутри периметра)

**Система кол-центра:**

* REST-клиент, обращающийся к API ставок

**Партнёрский кол-центр:**

* Получает файл (вручную загружается админом)

### **Альтернативы**

1. Передача данных в партнёрский call-центр по SFTP —  невозможно по ограничению
2. Автоматическое обновление по email с внешнего сервера —  высокие риски безопасности
3. Публикация ставок на сайте в отдельном разделе —  не подходит, данные должны быть только для операторов

### **Недостатки, ограничения, риски**

* Ручная передача файла повышает риск ошибок/задержек
* Партнёрский call-центр не сможет получить обновления в режиме реального времени
* Необходим контроль за конфиденциальностью передаваемой информации
* Требуется участие администратора банка (ручной процесс)
* Риски перегрузки API микросервиса при росте обращений от внутреннего call-центра
